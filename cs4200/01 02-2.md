# Properties of Task Environments

This is a list of possible properties of task environments.
- Parenthesized is the usually-observed property in the real-world.

## Fully Observable (v.s. Partially Observable)

An agent's sensors give it access to the complete state of the environment at each point in time

## Deterministic (v.s. Stochastic)

The next state of the environment is determined by the current state and the agent's action
- If the environment is deterministic except for the actions of other agents, then the environment is **strategic**

## Episodic (v.s. Sequential)

An agent's experience is divided into atomic "episodes"
- Choice of action in each episode depends only on the episode itself

## Static (v.s. Dynamic)

The environment is unchanged while an agent is deliberating.
- If the environment itself doesn't change with time, but the agent's performance score does, the environment is **semidynamic**

## Discrete (v.s. Continuous)

There's a limited number of distinct, clearly defined percepts and actions

## Single Agent (v.s. Multiagent)

An agent operating by itself in an environment.
- If it operates with others, it can be **competitive** or **cooperative**

# Five Basic Agent Types

(Arranged in order of increasing generality)

## Simple Reflex Agents

Simply maps "what the world is like now" $\to$ "what action should I do now".

```clrs
function SIMPLE—REFLEX—AGENT(percept) returns action {
	// 1. A set of condition-action rules
	static: rules, 
	// 2. Get state from percept
	state <- INTERPRET—INPUT(percept)
	// 3. Get the matching rule
	rule <- RULE—MATCH(state,rules)
	// 4. Return the appropriate rule
	action <- RULE—ACTION[rule]
	return action
}
```

Additional Notes:
- Infinite loops are often unavoidable for simple reflex agents operating in partially observable environments.
- A randomized simple reflex agent sometimes outperforms a deterministic simple reflex agent.

## Model-based Reflex Agents

Maps "what the world is like now" $\to$ "what action should I do now", but also tracks the part of the world it can't see now (maintains internal state).

```clrs
function REFLEX—AGENT—WITH—STATE(percept) returns action {
	// 1. current world state, set of condition-action rules, and previous action
	static: state, rules, action
	// 2. Get state from percept AND prior knowledge/action
	state <- UPDATE—STATE(state,action,percept)
	// 3. Get the matching rule
	rule <- RULE—MATCH(state,rules)
	// 4. Return the appropriate rule
	action <- RULE—ACTION[rule]
	return action
}
```

Essentially a SRA with a better understanding of the world, uses—
1. State
2. How the world evolves
3. What my actions do
—to understand "what the world is like now"

## Goal-based Agents

Maps "What the world is like now" $\to$ "what it will be like if I do action A" $\to$ "what action should I do now".

Essentially a MRA with an understanding of how the world and actions affect each other; and rather than getting rules from a set, it pursues goals to determine "what action I should do now".

## Utility-based Agents

Maps "What the world is like now" $\to$ "what it will be like if I do action A" $\to$ "How happy I will be in such a state" $\to$ "what action should I do now".

Rather than pursuing goals, uses a utility function to map a state or sequence of states onto a degree of happiness. This is used when you have multiple or conflicting goals (e.g., speed and safety)
