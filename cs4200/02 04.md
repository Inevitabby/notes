# Local Search Algorithms

> **Background** — So far we've systematically explored the search space with some memory to get a path to the goal.
> - But, the path is irrelevant in many optimization problems (e.g., we only want the solution)

**Local Search Algorithms**: Keep a single "current" state and try to improve it.
- Uses [little memory]{.underline} (usually constant amount)
- Find [reasonable solutions]{.underline} in [large/infinite state spaces]{.underline}
- Solve [optimization]{.underline} problems (problems with no goal test or path cost)

=== Hill Climbing Search ===
== aka: greedy local search ==

> "Like climbing Everest in thick fog with amnesia"

```clrs
// Return state is a local maximum 
function HILL—CLIMBING(problem) returns state
	local variables: current,
			 neighbor
	current <- MAKE—NODE(INITIAL—STATE[problem])
	loop do
		neighbor <- highest-valued successor of current
		if VALUE[neighbor] <= VALUE[current] then return STATE[current]
		current <- neighbor
```

This is a way to navigate the state space without memory. It gets stuck easily, and it not complete nor optimal.

> **Example**: Unstucking
> 
> Background: Hill Climb on 8-queens solves only 14% of problems with an average of 4 steps
> 
> If you allow **sideways moves** (doing a move that doesn't improve or hurt the current state), success rate goes to 94% with an average of 21 steps

# Local Beam Search

Idea: Track $k$ states. Start with $k$ randomly generates states.
- At each iteration, generate all successors of all $k$ states
- If goal not found, select the $k$ best successors from list and repeat

**Aside**: This isn't random-restart!

This isn't just running $k$ random-restart searches, because each branch we have to pick *something*.
