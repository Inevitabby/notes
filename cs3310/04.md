# Time Efficiency of Nonrecursive Algorithms

## General Plan for Analysis

1. Decide on parameter $n$ (input size)
2. Identify algorithm's [basic operation]{.underline}.
3. Determine [worst]{.underline}, [average]{.underline}, and [best]{.underline} cases for input of size $n$.
4. Set up a sum of the number of times the basic operation is executed.
5. Simplify sum using standard formulas and rules.

# Example: Maximum Element

```clrs
ALGORITHM MaxElement(A[0..n-1]
	// Determines value of largest element in a given array
	// Input: Array A[0..n-1] of real numbers
	// Output: Value of largest element in A
	maxval <- A[0]
	for i <- 1 to n-1 do
		if A[i] > maxval
			maxval <- A[i]
	return maxval
```

Q: Determine Best, Worst, and Average Case.

A:

Our basic operation is the comparison A[i] > maxval.

The best, worst, and average are all equal because we'll always iterate over everything in the array.

Look at the for loop, we do i <- 1 to n - 1.

$$
O(n) = \sum_{i=1}^{n-1} = ?
$$

Notice how each iteration does a single basic operation.
- Note how we don't do a basic operation for the first element, because we use it to initialize maxval, which is why we begin iterating from i=1 rather than i=0.

Thus,

$$
O(n) = \sum_{i=1}^{n-1} = n - 1 \in \theta(n)
$$

# Analysis of Recursive Algorithms

## General Plan

1. Decide on parameter $n$ (input size)
2. Identify algorithm's [basic operation]{.underline}.
3. Check whether # of times basic operation executes may vary on different inputs of the same size.
	- If it varies, the worst, best, and average cases must be investigated separately.
4. Set up a [recurrence relation]{.underline} with an appropriate initial condition expressing the # of times the basic operation is executed.
5. Solve the recurrence (or, at the very least, establish its solution's order of growth) by [backward substitutions]{.underline} or another method.
